# WorkBuddy 产物下载器（Chrome 扩展）v2.1

一键下载 [WorkBuddy](https://www.workbuddy.cn) 对话里的**产物**：逐个下载（保留真实目录结构）或打包成单个 ZIP。
v2.1 在 v2.0 的基础上重做了「并发 / 下载提醒 / 选择下载 / 进度口径 / 文件名」这几块体验。

## v2.1 更新内容

| 需求 | 实现 |
| --- | --- |
| 并发数可调 | 新增**设置页**，并发数可自由输入（1–64，默认 3），也可点 1/2/3/5/8/10 快捷值 |
| 不要下载提醒 / 动画 | 任务开始时调用 `chrome.downloads.setUiOptions({enabled:false})` 关闭下载气泡、下载栏与下载动画，任务结束自动恢复 |
| 下载完清除下载记录 | 每个文件完成后 `chrome.downloads.erase({id})`，只删本扩展产生的条目，你之前的记录不会被清空 |
| 日志默认展开 | 默认展开，可在设置里改成默认收起 |
| 双击单独下载 | 双击文件列表里的任意一行，立即单独下载该文件（无需勾选、不影响批量列表） |
| 文件勾选框 | 每行前面有勾选框，默认全部勾选；支持「全选 / 全不选」，逐个下载和 ZIP 都只处理勾选的文件 |
| 活跃文件显示不全 | 后台现在返回**全部**正在下载的文件，弹窗用「正在下载 N 个文件」列表逐个显示进度条 |
| 进度 / 速度 / 剩余时间单位 | 三项**分别**可选「文件体积」或「文件个数」，默认按文件体积；速度支持小数「个/s」 |
| .apkg 变成 .zip | 三层修复：① DNR 规则中和文件服务的 `Content-Type`；② `onDeterminingFilename` 强制文件名；③ 万一仍被改写，自动用页面直存重新保存为真实扩展名 |

## 安装 / 更新

1. 打开 `chrome://extensions/`
2. 右上角开启 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本目录（包含 `manifest.json` 的那一层）
4. **如果是覆盖更新：** 在扩展卡片上点 **刷新**（🔄），然后**刷新 WorkBuddy 页面**（Ctrl+R）
   - 旧页面里还运行着 v2.0 的内容脚本，不刷新会提示「页面里运行的还是旧版内容脚本」
5. 建议固定到工具栏

> 需要 Chrome 117+（`chrome.downloads.download` 自定义请求头、`setUiOptions`）。

## 使用

1. 打开任意 WorkBuddy 对话页（`https://www.workbuddy.cn/app/conversation/<任务ID>`）
2. 点击扩展图标，弹窗会自动扫描产物
3. 在文件列表里勾选要下载的文件（默认全选）
4. 选择：
   - **逐个下载（已选 N 个）**：保留 `/workspace` 下的真实子目录，支持任意大小文件
   - **打包 ZIP（已选 N 个）**：把所有勾选文件打成一个 Zip
   - **双击某一行**：只单独下载这个文件
5. 点右上角「设置」可调整并发数、日志默认展开、进度 / 速度 / 剩余时间的口径
6. 下载过程中可以关闭弹窗，任务在后台继续

## 设置说明

设置保存在 `chrome.storage.local`，修改后立即生效。

### 下载

- **并发下载数量**：同时进行的文件数。默认 3；可输入 1–64。数值越大越快，也越容易被服务器限速。
- **隐藏下载气泡与下载动画**：任务开始即关闭下载 UI，任务结束（完成 / 取消 / 出错）自动恢复。
- **下载完成后清除下载记录**：只 `erase` 本扩展创建的下载 ID，不会动你原有的下载历史。
- **自动修正被改写的扩展名**：见下文「关于扩展名」。

### 进度、速度与剩余时间

三项互相独立，可任意混搭：

| 项目 | 按文件体积（默认） | 按文件个数 |
| --- | --- | --- |
| 进度条 | 已下载字节 ÷ 总字节 | 已完成文件数 ÷ 总文件数 |
| 速度 | `12.3 MB/s` | `1.25 个/s` |
| 剩余时间 | 剩余字节 ÷ 字节速度 | 剩余文件数 ÷ 文件速度 |

## 关于扩展名（.apkg 变 .zip）

Chrome 在下载时会根据服务器返回的 `Content-Type` **强制改写扩展名**：WorkBuddy 文件服务把 `.apkg` 按 `application/zip` 返回，于是落盘就变成了 `CET4_词汇.zip`。这是 Chrome 的安全策略，单纯在 `chrome.downloads.download({filename})` 里写 `.apkg` 或使用 `onDeterminingFilename` 都不一定能绕过。

v2.1 的做法：

1. **运行时 DNR 规则**：对带 `X-Access-Token` 的文件服务请求，把响应头 `Content-Type` 改成 `application/octet-stream`，并移除 `Content-Disposition`（不影响 WorkBuddy 页面的图片 / 预览请求）。
2. **`onDeterminingFilename`**：按文件路径强制建议完整文件名（含扩展名）。
3. **兜底**：文件下载完成后校验落盘扩展名；若仍被改写，则用内容脚本 `fetch` + 中性 Blob + `<a download>` 重新保存为正确扩展名，并删除扩展名错误的副本、清理对应下载记录。

兜底会在日志里写明原因，且只对真正被改写的文件触发。

## 权限说明

- `downloads`：发起下载、读取字节进度、隐藏下载 UI、清除本扩展的下载记录
- `declarativeNetRequest`：中和文件服务的 `Content-Type`，避免扩展名被改写
- `storage`：设置、任务状态与日志持久化
- `alarms`：MV3 后台保活与任务恢复
- `activeTab` / `scripting`：页面早于插件安装打开时补注入内容脚本
- `https://www.workbuddy.cn/*`：读取对话页数据与会话接口
- `https://*.workbuddy.agentos-worker.net/*`：访问沙盒文件服务

扩展不收集、不上传任何数据，所有请求只发往 WorkBuddy 自己的服务。


## 工作原理

```
弹窗  --WBDA2_START_JOB(勾选的文件)-->  background（任务管理器）
                                            |
                                            |-- 逐个下载：chrome.downloads.download({
                                            |      url: <文件服务>/files?path=...,
                                            |      headers: [{name:'X-Access-Token'}],
                                            |      filename: 'WorkBuddy产物_任务_时间/真实/子目录/文件'
                                            |   })
                                            |   每 500ms 汇总 bytesReceived 与完成文件数
                                            |   完成 → 校验扩展名 → erase 下载记录
                                            |
                                            '-- ZIP：chrome.tabs.sendMessage 给 content.js
                                                  流式读取 + CRC + wbBuildZipAsync
                                                  <a download> 落盘
```

## 常见问题

**Q：更新后提示「页面里运行的还是旧版内容脚本」？**
A：按 Ctrl+R 刷新 WorkBuddy 页面即可。扩展更新不会自动替换已经注入到旧页面的脚本。

**Q：为什么下载时看不到任何下载气泡？**
A：这是 v2.1 的默认行为（设置里可关闭）。任务结束会自动恢复浏览器的下载 UI。

**Q：清除下载记录会不会把我以前的下载也删掉？**
A：不会。只会删除本扩展本次任务创建的下载 ID，历史记录保持原样，已下载的文件也不会被删除。

**Q：速度显示「—」或剩余时间不动？**
A：速度使用最近 6 秒的滑动窗口，刚开始下载的前 1–2 秒还没有足够样本，会显示「—」，随后自动出现。

**Q：并发调到很大会怎样？**
A：文件多、文件小时提升明显；但大文件并发会同时占用大量内存与带宽，建议 3–8。

**Q：ZIP 打包很久 / 页面卡顿？**
A：ZIP 需要把所有勾选文件读进页面内存再组装，文件很大时建议用「逐个下载」。超过 4GB / 65535 个文件会直接提示改用逐个下载。

**Q：所有文件都失败，日志显示 `SERVER_UNAUTHORIZED`？**
A：扩展会自动刷新一次会话 Token 再重试。若仍失败，请刷新 WorkBuddy 页面、确认登录态后再试。
